Lean4 · Z3 · SMT-LIB V2

SMT Proof Automation
for Lean4

Automatically prove Lean4 theorems using Z3. Blaster aggressively optimizes goals — often closing proofs without invoking the solver — then translates the remainder to SMT-LIB V2.

-- Prove commutativity of addition over Nat
#blaster [ ∀ (a b : Nat), a + b = b + a ]
✅ Valid

-- Catch a false claim and get a counterexample
#blaster [ ∀ (n : Nat), n < 10 ]
❌ Falsified
Counterexample:
 - n: 42
Why Blaster

Formal verification, automated

From simple arithmetic to complex inductive data types, Blaster brings SMT-powered proof automation to your Lean4 development workflow.

Aggressive Optimization

30+ rewriting rules covering beta reduction, function unfolding, let-expression inlining, Boolean simplification, and algebraic identities. Many theorems close to True without ever touching the SMT solver.

Full SMT Translation

Lean4 types and expressions faithfully translated to SMT-LIB V2. Supports Bool, Int, Nat, String, BitVec n, Fin n, SMTArray α, parametric & mutual inductives, and higher-order logic.

Z3 Integration

Automatic spawning of the Z3 process with configurable timeout, random seed, and verbosity. Dump the raw SMT-LIB query for debugging. Results interpreted as Valid, Falsified, or Undetermined.

Counterexample Generation

When Z3 returns sat, Blaster decodes the model into a concrete Lean4 counterexample — showing exactly which values falsify the theorem, including complex inductive structures.

State Machine Verification

Built-in #bmc (Bounded Model Checking) and #kind (K-Induction) commands for verifying invariants of Lean4 StateMachine instances up to a configurable depth.

Open Source

Apache 2.0 licensed. Benchmarked on the Lean Natural Number Game (103/117) and Set Theory Game (51/52). Contributions welcome.

How It Works

The three-step pipeline

Blaster uses a staged approach: optimize aggressively first, translate what remains to SMT-LIB, then let Z3 decide. Each step is optional and configurable via solver flags.

Step 1 — Optimize
Beta Reduction
Lambda applications are simplified by substituting arguments directly into the lambda body, reducing indirection.
Opt
Function Unfolding
Non-recursive, non-opaque definitions are expanded inline at every call site, exposing further simplification opportunities.
Opt
Let-Expression Inlining & Algebraic Rewriting
Let-bindings inlined; 30+ rules for Bool, Nat, Int, ITE, match, and function propagation normalize expressions to canonical form.
Opt
Early Exit: True / False
If the expression reduces to True, the theorem is declared Valid immediately. If it reduces to False, it is declared Falsified — no SMT query needed.
Opt
Step 2 — Translate
Type Mapping
Lean types → SMT sorts: Nat/Int → Int, Bool → Bool, BitVec n → (_ BitVec n), Fin n → Fin_n, Array α → (Array Int α).
SMT
Inductive Type Encoding
Parametric and mutually inductive types become uninterpreted SMT sorts. Predicate qualifiers constrain quantified variables to the right shape.
SMT
Quantifier & Application Translation
Universal/existential quantifiers become SMT forall/exists with type-predicate guards. Function applications mapped to SMT terms or define-fun declarations.
SMT
Step 3 — Solve
Valid (unsat)
The negation of the goal is unsatisfiable — the original theorem holds. The blaster tactic closes the goal with admit.
✅ Valid
Falsified (sat)
Z3 found a satisfying model for the negation. The model is decoded into a concrete Lean4 counterexample with actual values.
❌ Falsified
Undetermined (unknown)
The solver timed out or could not decide. The current goal is returned to the user for further manual reasoning.
? Unknown
